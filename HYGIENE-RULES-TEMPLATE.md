## CLAUDE.md hygiene — keep every CLAUDE.md slim

Applies to **every** `CLAUDE.md` I create or edit (global, project, nested). A CLAUDE.md is a rulebook loaded into context on every session — each line costs attention, so it must earn its place. Slim it without losing content (rule 3 names the exceptions).

1. **Behavior test.** Every line must change what I'd otherwise do. Cut background, descriptions, and anything derivable from the repo itself (file tree, code style, git history, package manifests) — or replace it with a one-line pointer.
2. **One home per rule.** Each rule lives in exactly one file; everything else links to it. Detailed procedures and step-by-step workflows belong in the skill/command that runs them or in `docs/` — CLAUDE.md keeps only the pointer plus a one-line summary of when it applies.
3. **Relocate what still changes behaviour** — to `docs/`, `README.md`, or the relevant skill, with a pointer left where it was. **Delete** what changes nothing, plus anything duplicated, superseded, or verifiably wrong — and verify first (grep for the referenced file/command; "renamed" is not "gone"). Every line gets a disposition; "relocate everything" is how a file grows a second home for dead content.
4. **Compress the writing.** Imperative bullets and tables over prose paragraphs. State the rule once; keep a "why" only when the rule is counterintuitive enough that omitting the reason invites a wrong "fix." At most one example per convention, and only where the format itself is the rule (e.g. a filename pattern). Provenance — who asked, when, which incident — goes in an HTML comment: stripped before the file reaches context, still visible on a `Read`.
5. **Prune on touch.** Editing any CLAUDE.md **proposes** the surrounding tidy in the same diff: drop rules referencing files/commands that no longer exist, merge overlapping rules, collapse rambling sections. Propose — a CLAUDE.md edit is the user's call, so the tidy rides along in the diff for approval, it is not applied unasked.
6. **Size guardrail.** ~150 lines **and ~1,500 words** per CLAUDE.md — the global file included, not just project ones. Words cost more than once: the file loads into every non-fork subagent and into every auto-mode classifier check. Crossing it is the trigger to extract sections (per rules 2–3) and leave pointers — not a hard cap that justifies deleting information.
7. **Structure for scanning.** Stable `##` sections grouped by topic, rules as bullets under them, most safety-critical rules first. No decorative headers for a single bullet.
8. **Review every CLAUDE.md I own against rules 1–7** when you touch one, or when asked — dead references, duplication across and within files, contradictions, verbosity. `/claudecodetidy:groom --user --report` is the cheap pre-check. Log the review date in the project's CHANGELOG or a note, so a gap is visible.
